# Decision: inconclusive economics; retain deterministic fixes

The economic question is unanswered. **E1 and E2 were not run:** authorized
model-campaign budget is zero and model/effort, isolated executor, independent
oracle and real client insertion identities remain unregistered. All model-token
and monetary comparisons are null. Do not start F3/E3/holdout, promote lean to
default or publish a release on this evidence. The appropriate next investment
is a bounded real-client exposure/insertion check, then an explicitly budgeted
comparison if that check supports it.

## Corrected causes and remaining hypotheses

Confirmed and corrected: exact source relocation previously generated false
added/removed relations; strict opt-in capture now rejects mistyped/excluded
scope instead of accepting an accidental empty future-file baseline. Duplicate
sites remain distinct; indistinguishable deletions retain uncertain evidence and
net multiplicity. Semantic endpoint/confidence changes are retained. Signature
source changes and exhausted correspondence budgets remain visible.

Implemented experimentally: deterministic lean presentation, separate required /
optional / compiler-test states, optional signature test collection, self-contained
source without acknowledgement management, and one bounded native insertion
adapter. These remove specific repeated metadata and workflow obligations.
They do not prove why the rc.1 application pilot consumed more or that a real
model benefits. Schema exposure, client forwarding, model behavior and total
economic effects remain hypotheses.

## Actually executed

Final v0.8.0 was rebuilt locked from the exact audited tag into a separate target.
Initial suite: 72 Rust tests; candidate `cargo xtask check`: 87 passing tests,
including source/transport/watcher/publication/invalidation regressions; Python
accounting/adapter suite: 20 passing tests. Native MCP intent and primitive
differentials against 0.6 passed across all ten providers and the Flutter fixture.
Android SDK checks passed. Prepared provider source assets match v0.8.0 byte for
byte; no Analyzer/provider upgrades or application execution was used.

The original deterministic rename gate passed: all 19 reference edges retained,
three collection calls including the expansion, 36,167 -> 23,789 response
characters (34.22% reduction against its 0.6 primitive replay). Schemas are
measured separately. A supplementary shorter legacy trace reduced only 3.62%
and failed that replay threshold; it remains recorded and is not the original
gate. These are response-volume tests, not paid model runs or economic replicas.

Quality parity is established only for the deterministic inventories tested.
Correspondence is deliberately conservative around repeated/reordered/changed
text, so some reviews still retain large ambiguous evidence. No rename/move
inference or runtime compatibility guarantee is added. Bounded deterministic
work and an adapter add maintenance complexity; no isolated microbenchmark yet
attributes runtime overhead to the diff/projection. Single full-query durations
are recorded without a speed claim. The agent schema grows from 8,940 to 9,671
compact UTF-8 bytes, a potential exposure penalty to measure in E1.

Audit/default behavior and persistent storage remain selectable. Strict capture,
lean rendering and optional exploration are explicit treatment choices with
[rollback instructions](integration.md). Real client support is still a gate.
No token/euro benefit, amortization or universal routing advantage is established.
Keep the deterministic fixes and the opt-in prototype; defer further token-saving
features until E1/E2 provide a valid decision. One additional diagnostic cycle
at most is preregistered before a stop/new investment decision.
