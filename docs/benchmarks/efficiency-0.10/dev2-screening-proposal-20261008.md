# Authorized dev.2 model screening — preregistration

Purpose: measure the new intent source policy and guidance against ordinary
source-only A, including every provider input/output token, repeated source reads,
failed attempts and static edit acceptance. This is a repeated screening on known
controlled tasks, not an independent confirmation or a 1.0 acceptance claim.

- Twelve existing static tasks, two per local/rename/signature/bug/flow/review
  family. One fresh A and one fresh D per task: **24 new solver turns**.
- D uses the tagged dev.2 binary and all eight frozen client modules; the current
  static workflow surface and source policy are actually applied. A has no PCG
  registration. Local tasks have no PCG registration in either condition.
- Same `gpt-6.1-sol`, reasoning effort `high`, serial paired schedule, fresh copied
  source workspaces, existing source-confinement/execution isolation and exact
  static oracles outside solver workspaces. No application execution.
- Authorized additional cap: **1,000,000 aggregate uncached input tokens**, checked
  after each turn. Final-turn overshoot may occur; the user explicitly accepted it.
  All input (including cache usage) and output still enter the primary task metric.
- No preparation AI, model judge, external solver retries or extra authorized
  solver attempts. Economic cost has not been verified. Unknown usage stops work.
- Freeze task/schedule/oracle/model/client/schema/binary/measurement identities
  and task-specific surfaces before the first paid turn. Do not replay old runs.

Record exact postimages, findings, source-read counts and actual provider usage,
including failures. Report limitations: syntactic/static acceptance is not runtime
correctness or broad quality noninferiority, and internal prompt insertion remains
qualified by the available real-client boundary evidence.

This campaign tests T3 policy behavior and aggregate current-client costs. Known
targets do not establish T4 seed-discovery improvement, and generic MCP cannot
observe model retention, so T6 stays disabled. Its end-to-end test requires a
different binding with explicit actual-context acknowledgement and a separately
defined experiment. The 1.0 +15% objective is reported as a future milestone,
not used to relabel this screening or the historical failed savings gate.

The previous 24-turn authorization is fully consumed. On 2026-10-08 the user
authorized this separate campaign: “Autorizzo 24 nuove run con questi limiti”.
The new campaign starts only after final dev.2 checks. Source-read diagnostics
report tool counts, returned characters and repeated file/line intervals per
attempt, including failed attempts; these are not measured model tokens.

it excludes graph windows, search results, line-number prefixes and newline
separators. Changed postimages have separate identities. Graph/direct overlap
and corrective-read necessity remain unknown.
No result-dependent task exclusions or external reruns are allowed.
