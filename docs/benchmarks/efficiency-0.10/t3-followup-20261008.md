## Correction and observability

The packaged workflow guide for `rename` and `change_signature` now tells the
agent to use exact hash-checked source and successful edit receipts already
returned, and to read back for a concrete missing fact, truncation, failed edit
or changed source. Write success remains separate from correctness; authorized
project checks remain necessary. Read tools are still available and no response
is suppressed. Other workflows, local zero-PCG routing and ordinary native
full/agent initialization are unchanged.

The targeted guide grows from 514 to 795 Unicode characters. That additional
instruction cost must be included in any model comparison; characters are not
measured tokens and a longer guide does not itself prove a saving.

`tool/efficiency_read_audit.py` supplies a reusable, bounded, hash-only receipt
audit. Failed writes, changed source, unknown/mismatched identities and failed
reads invalidate the observation used for comparison. State evictions and
unknown classifications remain visible. It never opens the source paths in
receipts, infers context retention, or labels a read unnecessary. Malformed,
oversized or excess evidence fails instead of producing a complete report.
