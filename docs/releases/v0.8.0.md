# PolyCodeGraph 0.8.0 — selective context and focused review

Large-file reviews could multiply the same coverage warning until the default
response budget failed. Version 0.8 deduplicates identical limits, reports explicit
collection/exploration/source completion, and localizes reviews to captured-source
changes with conservative contract/global fallback. Capture can return a minimal
baseline handle instead of every declaration.

- Optional locations, contracts, edit_context and full_evidence select useful source
  context while retaining required semantic site inventories and precision limits.
- Optional token estimates, cumulative record budgets and acknowledged source windows
  make expansion/retention explicit. Ordinary clients remain self-contained.
- Destination trace avoids unrelated branches; relation buckets preserve traversal
  budgets. Optional lexical discovery anchors candidates to existing semantic evidence.
- An opt-in agent toolset advertises five tools, with all original names/aliases
  accepted. Standard request metadata works directly with tool discovery clients.
- Runtime/intent/provider telemetry and a benchmark runner separate server work,
  payload size, client insertion and actual model usage. SQLite schema 4 reads schema
  3 and adds an edges(file) index plus independent transactional storage revisions.

The [application pilot](../benchmarks/efficiency-0.8-application/report.md) accepted
18/18 tasks. Observed uncached input per accepted task for rc.1 is 13.7% lower than
0.7, but 89.7% higher than no graph; local work increases 54.5%. One replica per
cell and incomplete client telemetry mean G2 fails and no robust/monetary benefit
is established. Signature/review remain optimization priorities. Final 0.8 fixes
metadata handling and docs after that pilot; no final-release AI retest is claimed.

Existing primitive calls/default full tool advertisement and provider resolvers
remain compatible; the new options are explicit. [Migration/rollback](../migration-0.8.md)
documents views, estimates, cursors, acknowledgement resets and separate rollback
caches. The [earlier deterministic rc report](../benchmarks/efficiency-0.8/report.md)
remains frozen rather than retroactively rewritten into an AI result.

[Final local validation](v0.8.0-validation.json) records the final Linux binary,
72 Rust tests, 13 accounting tests, native differentials, metadata/EOF, Android,
package relocation and preserved rename evidence.

Native archives target Linux x64, Windows x64 and macOS Intel/Apple Silicon. Exact
release CI, platform/native/SDK/package validation and archive checksums are recorded
in the GitHub release. A failed economic target is visible independently of product
compatibility validation; release does not declare that target achieved.
